LayerPattern Tool

Turns pallet layer drawings into symbolic PLC parameters: every package centre is a combination of the package length KL, the package width KB and the safety gap D, so one pattern works for every package size the PLC receives.

Workflow

  1. Start page: New project, Open project, or Import generated TIA DB.
  2. PDF tab: Import PDF (several are possible), select pages in the thumbnails.
  3. Recognize the selected pages, or switch on Region and draw a rectangle around one pattern.
  4. Review the proposals (green: fine, yellow: uncertain, red: incomplete). Check the ones you want, enter the real KL, KB and D on the right and press Accept. Nothing becomes project data before that.
  5. Editor tab: open each pattern, correct packages, edit the placement sequence, check the dimensions.
  6. Enter the intended real KL, KB and D, then Verify (Ctrl+Enter) each pattern.
  7. Resolve duplicates. Mirrored patterns are only reported.
  8. Save the project. Export becomes available when every pattern is valid and verified.

You can also build a pattern by hand: New Pattern starts the Add Package tool directly.

Add Package: the package follows the cursor, snap targets light up, R toggles the orientation, a click places it (added at the end of the sequence), Esc ends the tool. The first package of an empty pattern always sits at the origin.

The right-hand panel shows the pattern status, the example values, the exact parameters of the selected package (read only) and the display options. The context menu of the drawing and of the pattern list offers the important commands as well.

PDF recognition

Works on vector drawings and on PDFs made of images. Only brightness and edges are used: colours never decide anything, not even which package is rotated. Recognized are filled and outlined rectangles, slightly rounded corners and pages tilted by up to about 5°. Text, numbers, arrows and dimensions on the page are ignored; PDF dimensions are never read.

  • Patterns may be separated only by white space. A gap of more than about half a package starts a new pattern.
  • Touching packages are separated along their lines. A block without separators is split by the repeated package size and marked yellow.
  • Drawings are schematic: the tool reads which packages touch and which edges are flush and rebuilds the pattern from that, not from drawn millimetres. Different drawn sizes give a yellow note.
  • Sensitivity (Options): Low finds only clear shapes, High also faint ones.
  • Recognition runs in the background; Cancel or Esc stops it and leaves the project unchanged.
  • Recognizing an area again creates a new proposal. If a pattern was accepted from that area before, both are shown side by side: Accept adds a new pattern, Replace overwrites the old geometry (undoable). Manual edits are never overwritten automatically.
  • Source View (Pattern group) shows the PDF page and region a pattern came from. The project stores only the PDF path; if the file moved, patterns stay editable and Relink restores the source view.

Symbolic snapping

A package never has a free position. On each axis it is related to one other package:

  • adjacent with exactly one D in between (left/right, above/below),
  • flush edges (left, right, top or bottom),
  • centred on the other package,
  • half step: its centre on an edge of the other one, or an edge on its centre (brick bond).

While dragging, the nearest relation within reach is shown as a guide line with its name, and the reference package is outlined. On release the nearest relation is always applied exactly, so a drop never leaves an arbitrary position. If several relations land on the same spot, the simplest one wins. Other gaps than one D cannot be entered. Rotating a package keeps its centre and snaps it again.

Placement sequence

The numbers on the packages are the palletizing order. Moving a package never changes it.

  • Auto Order: rows from bottom to top, each row from left to right.
  • Sequence tab: drag rows to reorder.
  • Click Order: click the packages in the wanted order; it finishes after the last one (Enter finishes early). Esc restores the previous sequence. The whole click order is one undo step.

Deleting packages closes the gaps automatically; numbers are always 1..n without duplicates.

Verification

A pattern is either verified or not verified. Verify is possible only for a structurally valid pattern and first shows a summary of everything the PLC will receive.

Changing a package position, orientation, the package set, the sequence or the PatternId resets the verification. Changing KL, KB, D or the pallet does not - unless the new values change the exported coefficients (see Limits); then the pattern shows that it must be verified again.

Blocking problems: no packages, more packages than the maximum (Options, default 64), overlapping packages, a gap smaller than D between facing packages, packages not connected to the rest (diagonal contact does not count), coefficients outside 1/16 steps, a PatternId used twice, an exactly identical pattern elsewhere in the project.

Duplicates and similar patterns

Two patterns are duplicates if they have the same packages at the same relative positions with the same orientations - wherever they are and whatever their sequence. A duplicate blocks verification and export until one of them is changed or deleted.

A rotated pattern is a different pattern. A mirrored pattern is reported as similar (MIRROR badge) but allowed. Rotate Pattern offers rotated copies (safer, new PatternId) and in-place rotation by 90°, 180° and 270°; the sequence is kept.

KL, KB, D, pallet and orientation

  • KL long side, KB short side, D safety gap - whole millimetres, KL ≥ KB. They are stored per pattern for drawing and checking only and are never exported.
  • The pallet (width = X, length = Y) is a reference drawn below the pattern and centred with it. It is never exported; overhang is allowed and never blocks anything.
  • BaseOrientation 0: KL along pattern X; 90: KL along pattern Y. If KL equals KB the orientation cannot be seen and is exported as 0. The PLC combines it with the label scan; that is not part of this tool.
  • Pattern coordinates: X to the right, Y upwards. The Symbolic / Numeric switch shows dimensions as KL/KB/D expressions or in millimetres for the current example values.

Coefficient formulas

RelativeCenterX = KxL*KL + KxB*KB + KxD*D
RelativeCenterY = KyL*KL + KyB*KB + KyD*D

The reference point is the centre of the bounding box over all package outer edges (not the area centroid; holes do not matter). The PLC adds the pallet centre: PackageCenter = PalletCenter + RelativeCenter.

Coefficients are exact multiples of 1/16 (0.25, -0.5, 1.0 ...) and therefore exact as REAL.

Project file and DB import

Projects are saved as *.layerpattern.json (manual save; no autosave). They contain the patterns with exact symbolic positions, sequence, verification, example values, the list order, the PDF paths and the source regions - not the PDFs themselves and no recognition proposals.

Import DB reads a DB source generated by this tool and starts a new project from it. Because KL, KB and D are not in the DB, you enter example values to display the patterns. Imported patterns are not verified.

Excel and TIA Portal export

Export writes into one folder, from one consistent snapshot, and only after every file has been generated and checked (nothing is left behind if anything fails):

  • <name>_Patterns.xlsx: sheets Patterns (PatternId, FirstPackageIndex, PackageCount) and Packages (index, PatternId, Sequence, BaseOrientation, six coefficients, readable X/Y formulas).
  • <name>_Types.udt: the two data types. <name>_Patterns.db: the DB with start values. Import both into TIA Portal V21 as external sources, types first, then "Generate blocks from source".

DB layout (names changeable in Options): PatternIndex[1..99] - entry = PatternId, 0/0 means no pattern - and the flat array Package[1..n], ordered by PatternId and sequence. A package is Package[PatternIndex[id].FirstPackageIndex + Sequence - 1].

Global package indices are not stable: deleting or adding a pattern compacts the array. PLC logic must always address packages by PatternId and Sequence.

Messages

Short messages appear in the status line at the bottom; warnings are amber, errors red. Long messages unfold for a moment; a click shows them again. Unexpected errors offer Details. No log files are written.

Recognition marks: no colour = fine, yellow = uncertain (sizes differ, orientation not readable, separated by size), red = incomplete (positions estimated, overlap, not connected).

Limits of the check

A pattern is checked for the KL, KB and D entered in the tool. It is not proven for every possible package. Where the outline is not a rectangle, the bounding box depends on the sizes; the tool then shows the condition under which the coefficients stay valid, e.g. 2·KB + D ≥ KL. Enter the intended real values before verifying, and check again in the tool before the PLC uses different values.
