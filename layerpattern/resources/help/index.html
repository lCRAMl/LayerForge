LayerPattern Tool - Help

Turns pallet layer drawings into symbolic PLC parameters: every package centre is written with the package length KL, the package width KB and the safety gap D, so one pattern works for every case size the PLC receives.

Quick start

  1. Start tab: New project.
  2. PDF tab: Import PDF, select pages, Recognize.
  3. On the right enter D and the pallet, select a proposal, press Fit to pallet (or type the real KL and KB), then Accept.
  4. Editor tab: check every pattern, correct packages and sequence.
  5. Verify each pattern (Ctrl+Enter).
  6. Save, then Export.

Without a PDF: New Pattern and place packages with Add Package.

Projects

New, Open, Save, Save As

WhereCommand bar Project, or the Start tab. Ctrl+N, Ctrl+O, Ctrl+S, Ctrl+Shift+S. Recent projects (up to five) on the Start tab.
RequiresSave and Save As need an open project. With unsaved changes (an asterisk in the title) New, Open and closing ask Save / Discard / Cancel.
ResultA file *.layerpattern.json. The first save names the project after the file. There is no autosave.

A project stores the patterns (exact positions, sequence, verification, example values, drawing proportions), the list order, the PDF paths and source regions. It does not store the PDFs and no unaccepted proposals.

Import a generated DB

WhereStart tab Import generated TIA DB, or Project > Import DB.
RequiresA *_Patterns.db written by this tool (the header names the generator and format version). Other DB sources are refused.
ResultA new, unsaved project. Because KL, KB and D are not in the DB you enter example values once. All patterns start not verified; PDF links are not restored.

PDF tab

Import PDF

WherePDF tab, command bar PDF > Import PDF. Several files at once are fine; switch between them with the box above the page thumbnails.
RequiresAn open project.
ResultThumbnails appear page by page in the background. Only the path is stored. Undoable.

Recognize pages or a region

WhereRecognize: all selected thumbnails (Ctrl/Shift+click), or the shown page. Region: switch on, then drag a rectangle on the page around one pattern. Cancel or Esc stops.
RequiresThe PDF file is reachable. The example values on the right must be valid (KL ≥ KB) - they are used to judge the proposals.
ResultProposals, shown as coloured outlines on the page and in the list on the right. The project is not changed. A new result for a page or region replaces the earlier unaccepted proposals there.

What is recognized: filled and outlined rectangles, slightly rounded corners, pages tilted up to about 5°, vector drawings and scanned images. Only brightness and edges count - colours never decide anything, not even which case is rotated. Text, numbers, arrows and dimensions are ignored. Patterns may be separated by white space alone. Drawings are usually not to scale: the tool reads which cases touch and which edges are flush, and rebuilds the pattern from that. Options > Recognition sensitivity: Low finds only clear shapes, High also faint ones.

Proposals: check, size, accept

WhereRight side of the PDF tab. Click a proposal (in the list or on the page) to see its numbers and messages. The check boxes choose what Accept takes.
RequiresAccept: at least one checked proposal and valid example values. Accept All Valid takes every proposal without a red mark.
ResultNew patterns with the next free PatternIds, the example values from the fields, the drawing proportions and a link to their PDF region. One step, Ctrl+Z removes all of them again. Discard drops checked proposals.

Colours: green = fine, yellow = uncertain (drawn sizes differ, orientation not readable, cases separated by their size), red = incomplete (position estimated, overlap, not connected; not checked by default). Fit to pallet in the example values fills KL and KB for the selected proposal - see Fit to pallet. Different case sizes on one page: accept proposals one by one, or accept all and use Fit to pallet per pattern in the editor.

Recognizing again an area that was accepted before shows old and new side by side: Accept adds a new pattern, Replace pattern n overwrites the old geometry (undoable). Manual edits are never overwritten automatically. Unaccepted proposals are lost when the project is closed - the tool asks first.

Source view and relink

WhereEditor, Pattern > Source View, or the pattern list context menu. PDF > Relink in the PDF tab.
RequiresThe pattern was accepted from a PDF. If the file has moved, Source View reports it and Relink lets you choose the new location.
ResultThe PDF tab opens the page and frames the original region. Patterns stay fully editable even when the PDF is missing.

Pattern list and pattern commands

Each row shows the preview, PatternId, number of packages, a shield when verified, and a badge: DUPLICATE, ID TWICE, INVALID (red) or MIRROR (amber). Hover a row for a large preview. Drag rows to change the list order (it has no effect on the export). The sort button shows the list by PatternId for a moment. Right-click for the pattern commands.

New PatternPattern group. Needs a project. Gets the highest PatternId + 1 and the default example values (Options); the Add Package tool starts right away.
Delete PatternAsks first; a stronger warning for verified or DB-imported patterns, because the PLC may use that PatternId. Undoable. Later patterns keep their IDs.
Change ID1..99, not used by another pattern. Warns about PLC references and resets the verification.
Rotate PatternMenu: Rotated copy 90°/180°/270° (safer: new pattern with a new ID) or rotate in place. The sequence is kept, orientations follow. A rotated copy identical to an existing pattern is reported (and blocked as a duplicate).

What the drawing shows

Packages with their sequence number and a thin line along KL (the BaseOrientation), the pallet below, the pattern centre (= pallet centre), the pattern size (below and left) and the pallet size (above and right). For one selected package: its size, its centre relative to the pattern centre (X and Y) and the gaps D to its neighbours. Properties > Display switches pallet, sequence numbers, orientation lines, snap guides, package centres, bounding box and overhang, and Symbolic / Numeric (also View > Numeric): KL/KB/D expressions or millimetres for the current example values. Red hatching marks packages that overlap, are closer than D, or are not connected.

Snapping

A package never has a free position. On each axis it relates to one other package:

  • adjacent with exactly one D in between (left/right, above/below),
  • flush edges (left, right, top or bottom),
  • centred on the other package,
  • half step: its centre on an edge of the other one, or an edge on its centre (brick bond).

While dragging, the relation in reach is drawn as a guide line with its name, and the reference package is outlined; on release the nearest relation is applied exactly. If several land on the same spot, the simplest wins. Gaps other than one D cannot be created.

Placement sequence

Auto OrderSequence group or Sequence tab: rows from bottom to top, each left to right.
Drag and dropSequence tab on the right: drag rows to a new position.
Click OrderClick the packages in the wanted order; it finishes after the last one (Enter finishes early, the rest keep their order). Esc restores the previous sequence. One undo step.

Moving a package never changes its number. Numbers are always 1..n without gaps or duplicates. A changed sequence resets the verification.

Example values (KL, KB, D, pallet)

WhereEditor, Properties > Example values, per pattern. For new patterns the defaults come from Options; for accepted proposals from the fields in the PDF tab.
RequiresWhole millimetres, KL ≥ KB > 0, D ≥ 0, pallet > 0. A field is taken over with Enter, Tab or by leaving it.
ResultThe drawing and all checks use the new values. They are never exported. Verification stays - unless the new values change the exported coefficients (the pattern then says so).

All packages of a pattern have the same size; single packages cannot be scaled. If a value only fits together with the next one (KL 320 while KB is still 400), it waits as "not applied yet" until the pair is consistent - type the values in any order. Revert drops it. Swap pallet exchanges width and length.

Fit to pallet

WhereEditor: Properties > Example values > Fit to pallet, then Alternatives for the next best sizes. PDF tab: Fit to pallet under the example values, for the selected proposal.
RequiresA pattern with packages (or a selected proposal). Enter D and the pallet first - they are kept as they are.
ResultKL and KB on a round grid. In the editor applied at once (one undo step); in the PDF tab written into the fields for Accept. The status line shows pattern size and pallet usage.

The arrangement never changes; only the case size is searched:

  1. The pattern stays as drawn. Edges that are flush in the drawing stay flush (within one grid step; safety gaps excepted). The drawing proportions, e.g. 3·KL = 4·KB, are shown in the pattern status and in the proposal details.
  2. Only multiples of the grid (Options, default 10 mm), KL ≥ KB, and only sizes for which the pattern is valid.
  3. Fit = overhang beyond the pallet counted twice + unused pallet edge, width plus length.
  4. Among all sizes at most the tolerance (Options, default 25 mm) worse than the best fit, the roundest wins: hundreds before fifties before tens. Then less overhang, then more used area.

If the drawing's proportions cannot be reached on this pallet, the best size without them is offered and the status line says so. Overhang is allowed. After editing, proportions that no longer match the pattern are ignored. Patterns built by hand or imported from a DB have no drawing proportions; only rules 2-4 apply.

Validation and verification

WhereCheck > Verify, Ctrl+Enter, the Verify button in Properties, or the pattern list context menu.
RequiresThe pattern is valid (no red problem in Properties) and not yet verified. Enter the intended real KL, KB and D first.
ResultAfter a summary of everything the PLC will receive the pattern is verified (green shield).

Blocking problems (red): no packages; more than the maximum (Options, default 64); overlapping packages; a gap smaller than D between facing packages; packages not connected to the rest (corner contact does not count); coefficients that are not multiples of 1/16; a PatternId used twice; an identical pattern elsewhere.

Notes (amber, do not block): KL = KB (orientation exported as 0), mirror image of another pattern, "verify again" after example values changed the coefficients.

Verification is reset by any change to what is exported: package position, orientation, adding or deleting packages, the sequence, the PatternId. It is kept for example values, pallet, view settings and PDF links.

Coefficients valid while: where the outline is not a rectangle, the pattern centre depends on the sizes. The condition shown (e.g. 2·KB + D ≥ KL) is where the exported coefficients hold; it is also in the Excel export.

Duplicates and mirror images

Duplicate: same packages at the same relative places with the same orientations - wherever they lie and whatever their sequence. Blocks verification and export until one of them is changed or deleted. Mirror image (left-right or top-bottom): reported, allowed. A rotated pattern is a different pattern.

Export

WhereCommand bar Output > Export.
RequiresEvery pattern of the project is valid and verified, and the project has at least one pattern. The button tooltip lists what is missing. Target files must not be open in Excel or TIA.
ResultIn one folder, written in the background from one snapshot. Files are first written and checked in a temporary folder; only then they replace the old ones. If anything fails, nothing is changed.

The dialog chooses Excel and/or TIA sources, the folder and the file name prefix, and shows the file names and the Siemens names (set in Options).

Excel: <prefix>_Patterns.xlsx

PatternsOne row per pattern: PatternId, FirstPackageIndex and PackageCount (the same as PatternIndex[PatternId] in the DB - use it to compare TIA watch tables with Excel), Width and Height of the outline as formulas (e.g. 3*KL + 2*D, useful for overhang checks in the PLC) and ValidWhile (the condition above, or "always").
PackagesGlobalPackageIndex, PatternId, Sequence, BaseOrientation, the six coefficients and the readable X/Y formulas. Sorted by PatternId and sequence; patterns alternate in shade.

TIA Portal V21: <prefix>_Types.udt and <prefix>_Patterns.db

Always both together. Import them as external sources, types first, then Generate blocks from source. Plain ASCII, generated header with tool, format version and date.

PatternIndex[1..99]: entry = PatternId; 0/0 = no pattern. Package[1..n]: all packages, by PatternId and sequence. A package is Package[PatternIndex[id].FirstPackageIndex + Sequence - 1]. Global package indices are not stable - deleting or adding a pattern compacts the array. PLC logic must always address packages by PatternId and Sequence.

Concepts and formulas

KL, KB, DCase length, case width (KL ≥ KB), safety gap. Neighbours have exactly one D.
BaseOrientation0 = KL along pattern X, 90 = KL along pattern Y. The PLC combines it with the label scan; that is outside this tool.
CoordinatesX to the right, Y upwards. Reference point: centre of the bounding box over all package edges (not the area centroid; holes do not matter). The pallet is centred on it.
FormulasRelativeCenterX = KxL*KL + KxB*KB + KxD*D
RelativeCenterY = KyL*KL + KyB*KB + KyD*D
PackageCenter = PalletCenter + RelativeCenter (in the PLC)
CoefficientsExact multiples of 1/16 (0.25, -0.5, 1.0 ...), so they are exact as REAL.
LimitsA pattern is checked for the example values entered in the tool, not for every case size. Before the PLC uses other sizes, check them in the tool (and mind Coefficients valid while).

Questions and answers

Why is Export greyed out?

At least one pattern is invalid or not verified (or the project is empty). Hover Export - the tooltip lists the PatternIds. Verify each of them (green shield in the list).

Why can I not verify?

The pattern has a red problem in Properties, or it is verified already. Typical: packages closer than D, a package not touching the rest, or an identical pattern elsewhere.

The pattern looks different from the PDF.

PDF layer drawings are rarely to scale - the same case is often drawn with different proportions standing and lying. The editor is to scale for the entered KL, KB and D. Use Fit to pallet or enter the real case size; the drawing proportions in the pattern status tell you what the drawing intends.

The pattern is far too big for the pallet.

The default example values (600 x 400) were used. Enter D and the pallet, then Fit to pallet.

My KL entry is "not applied yet".

It is smaller than the current KB. Enter KB too; both are applied together. Revert drops the entry.

Source View says the PDF is missing.

The file was moved or renamed. PDF > Relink in the PDF tab points the project to the new file.

Where are my settings?

In the registry for your Windows user (LayerPattern / LayerPatternTool). Patterns and their example values are in the project file.
